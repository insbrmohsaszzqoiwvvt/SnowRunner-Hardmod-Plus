# Hard Mode Plus — итоги работы и как продолжить на ПК

Репозиторий: `insbrmohsaszzqoiwvvt/SnowRunner-Hardmod-Plus`, ветка
`claude/cool-heisenberg-pqxk2k`, PR #1 (ещё не влит в основную ветку).
Готовый архив для игры — `Hard Mode Plus.zip` в корне репозитория.

## Что есть

Патчер правит скомпилированные скрипты игры (`[ssl_cache]/initial_*.sslbundle` внутри
`preload/paks/client/initial.pak`). Он всегда собирает файл заново из оригинала
(`Hard Mode Plus/backup/initial.pak`), поэтому патчи можно включать, выключать и менять их
значения в любом сочетании. Запуск — `patch_initial_pak.bat`, возврат оригинала —
`restore_initial_pak.bat`, настройки — `settings.ini` (в нём же `game_dir`).

| Ключ в settings.ini | Что делает | В игре |
|---|---|---|
| `contest_attempts`, `contest_reward_factor`, `contest_xp_factor` | попытки, награда и опыт за испытания | были до этой работы |
| `trailer_selling` | продажа прицепов в Сложном режиме | были до этой работы |
| `skip_bootup` | пропуск стартовой заставки | были до этой работы |
| `garage_body_repair` | бесплатный ремонт корпуса в гараже | были до этой работы |
| `repair_from_nearby` | ремонт от любой сервисной машины, аддона или прицепа рядом | проверялось в игре по ходу работы |
| `repair_parts_transfer` | перекладка запчастей и колёс между сервисными аддонами и прицепами | проверялось в игре по ходу работы |
| `repair_single_wheel` | замена отдельного колеса: стрелки у строки «Колёса», маркер на колесе | работает («вроде работает как надо») |
| `winch_unpack_cargo` | распаковка и упаковка груза того, за кого зацеплена лебёдка | проверялось в игре по ходу работы |
| `cargo_loading_price` + `cargo_loading_logs_short/medium/long` | цена автопогрузки: $150 за слот груза; брёвна ×1/×2/×3 | явно не подтверждено |
| `headlights_follow_player` | фары привязаны к игроку (см. ниже) | работает, кроме одного места |

Подробное описание патчей сервиса и шаги проверки — `Hard Mode Plus/README_SERVICE.md`.

## Фары — где остановились

Установлена в игре версия из коммита `bfd7541` (4 файла: `service_patches.py`,
`patch_initial_pak.py`, `settings.ini`, `README_SERVICE.md`). Что она делает:

* при пересадке фары нового грузовика ставятся такими, какими были у игрока в прошлом
  грузовике (включены или выключены) — **работает**;
* после выхода в гараж или смены карты фары игрока не сбрасываются;
* покинутому грузовику фары включаются снова, а через `headlights_follow_player` секунд
  (60 по умолчанию) отложенная задача их гасит.

**Открытая проблема:** покинутый грузовик не освещает территорию.

Что известно:

* фары в скриптах — только `Truck.EnableHeadLight(bool)` (родной метод движка) и флаг
  `TruckInput.isHeadLight`; больше методов для света у `Truck` нет (есть ещё мигалка
  `ActivateRotatorFlare`);
* при пересадке скрипты фары не гасят — это делает сам движок;
* скорее всего, движок отбрасывает свет на землю только от текущего грузовика (по
  производительности), а у остальных максимум светятся сами фары. Тогда через скрипты это
  не исправить.

Что проверить в игре:

1. Светятся ли у покинутого грузовика сами фары (стёкла и лампы), хотя света на земле нет.
   Если светятся, флаг включён и упираемся в движок.
2. Погасли ли фары у покинутого грузовика полностью сразу после пересадки, или через
   минуту.

Варианты: оставить как есть, поставить `headlights_follow_player = 0` (покинутый гасит фары
сразу), или искать в движке отдельный механизм света неактивных грузовиков. Последнее —
уже не правка скриптов.

**Про коммит `e65a097`** (последний на ветке). Он добавляет повторные включения фар в
течение 6 с после пересадки и два поля в `TruckState`. Пользователь его не ставил:
предыдущая версия уже работает, причина жалобы была в том, что патч не применили. Этот
коммит в игре не проверен. Если он не нужен, его можно откатить:
`git revert e65a097`. Файлы из него сохранены у пользователя отдельно.

## Устройство (для доработки)

* `Hard Mode Plus/patch_initial_pak.py` — патчер: чтение настроек, бэкап, сборка
  `initial.pak`. Простые патчи описаны в нём самом (`PATCHES`).
* `Hard Mode Plus/sslpatch.py` — библиотека: разбор и сборка модулей SSL (protobuf),
  строки, типы, импорты, мини-компилятор байткода (выражения, `If`, `While`, `ForEach`,
  делегаты), поиск кода по шаблонам, проверка стека.
* `Hard Mode Plus/service_patches.py` — патчи сервиса и фар (`apply_*`). Места в коде
  ищутся шаблонами инструкций, слоты — по объявлениям классов, поэтому после обновления
  игры патч либо применится, либо остановится с понятной ошибкой.
* Файлы в `Hard Mode Plus/` — с переводами строк CRLF; при правке их надо сохранить.
* Поле в класс игры можно добавить (`add_class_field`) только если у класса нет своих
  методов, иначе сдвинутся слоты. Так добавлены поля в `PopupRepairUiViewData2` (колёса)
  и, в `e65a097`, в `TruckState`.

Байткод: инструкция — varint, младший байт — опкод, операнд со смещением 0x800000.

* Стек и данные: 01 зарезервировать, 02 снять, 03 null, 04 int, 05 bool, 06 константа,
  07 локальная (0 = this), 08 глобальные, 0a/3c чтение/запись поля, 3b запись в локальную.
* Вызовы: 0d вызов (аргументы кладутся в обратном порядке, затем объект и их число),
  0f событие, 10/11 подписка/отписка, 14 делегат.
* Переходы: 12/13 возврат, 16 если ложь, 18/19 если ложь/истина (значение остаётся),
  1a безусловный.
* Арифметика и сравнения: 20 +, 24 −, 27 ×, 2a ÷, 1d −x, 1b не, 30 сравнить (7 =, 8 ≠,
  годится и для bool, строк и объектов), 31/32 сравнить целые/дробные (9 <, 10 >).
* Массивы: 3f a[i], 41 размер.

Полезное из исследования:

* **Фары.** Контроллер управления — `game.truck_manager.truck_input_controller`,
  класс `TruckInputController`.
  * `SetActiveTruck(truck)` вызывается при каждой смене грузовика и без грузовика
    (`LeaveTruck`: гараж, смена карты).
  * Поле `currHeadLightsOn` — состояние фар, `SetLights(bool)` включает фары текущего
    грузовика.
  * Метод `UpdateTruckStickersMaterial(Truck)` игра вызывает только из
    `SetActiveTruck`. Патч фар использует его как отложенную задачу.
  * Задачи ставятся через `scheduler.Delay(мс, делегат)`; `CancelAll` выполняется при
    выгрузке карты.
* **Двигатель.** Задержка выключения двигателя скриптами — это `delayBeforeTurningOffEngineSec = 240`.
  Это бездействие игрока в текущем грузовике. Глушение покинутых грузовиков делает движок.
* **Погрузка.** Окно погрузки — `ui.components.popups.cargo.popup_cargo_loading_ui_controller`
  (`InitContent`, `TryShowCargoPreview`, `Action`).

## Инструменты разработки (`dev_tools/`)

Скопированы из облака. Пути в них облачные, на ПК их надо поправить:

* `DATA = '/tmp/claude-0/.../scratchpad/data/'`;
* `sys.path.insert(0, '/home/user/SnowRunner-Hardmod-Plus/Hard Mode Plus')`.

Данные для них:

* `data/release.sslbundle`, `profile.sslbundle`, `debug.sslbundle` — достать из
  `backup/initial.pak` (zip) файлы `[ssl_cache]/initial_*.sslbundle`;
* база классов `classdb*.pkl` строится сама: `SSL_BUNDLE=... SSL_DB=... python db.py`.

Скрипты:

* `ssl.py`, `pip.py` — разбор бандла и модулей.
* `dis.py` — дизассемблер: `python dis.py <модуль> > out.dis`. Есть также
  `Hard Mode Plus/tools/ssl_dis.py`.
* `grepall.py`, `grepctx.py` — поиск по дизассемблеру всех модулей (подстрока, не regex).
* `verify.py` — проверка глубины стека во всех функциях. В оригинале 3 ошибки из-за редких
  опкодов, это норма.
* `vm.py` — мини-модель исполнения байткода с подменой методов игры.
* `test_*.py` — тесты патчей на этой модели:
  * `test_lights.py` написан под `e65a097`;
  * `test_cargo_price.py` — погрузка;
  * `test_wheels_*`, `test_repair_r3`, `test_view_r3`, `test_hud_r3` — окно ремонта и меню.
* `run_apply.py` — применить все патчи сервиса к бандлу: `python run_apply.py release`.

Переменные окружения: `SSL_BUNDLE` — какой бандл читать, `SSL_DB` — база классов. Тестам
окна ремонта нужна база, собранная из уже пропатченного бандла (там новые поля классов).
